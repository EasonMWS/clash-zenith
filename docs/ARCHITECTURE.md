## 架构

```
Zenith.exe
├─ main.go          启动流程、窗口、命令行参数
├─ app.go           编排层：store + core + optimizer + sysproxy
├─ store.go         设置/订阅/节点的 JSON 持久化（原子写）
├─ subscription.go  订阅抓取 + YAML 子集解析器 + 各类分享链接
├─ config.go        生成 mihomo 的 config.yaml，校验自定义规则
├─ core.go          mihomo 进程管理 + REST API 封装
├─ optimizer.go     日志 + 边缘 IP 扫描与优选
├─ sysproxy.go      注册表读写 + 安全判定
└─ server.go        本地 HTTP 服务（API + 静态界面）
```

进程模型：

```
Zenith.exe ──启动──> mihomo.exe（子进程，隐藏窗口）
     │                    │
     │  REST 127.0.0.1:7797（控制端口）
     └────────────────────┘
     │
     └── HTTP 127.0.0.1:7799（界面）──> Edge --app 窗口
```

所有监听都绑在回环地址，局域网访问不到。内核控制端口带一个随机 secret。

## 一次切换节点发生了什么

这是和多数客户端最本质的区别。

1. 界面 `POST /api/switch {"name":"优选03"}`
2. `App.Switch()` 调 `Core.Select("PROXY", name)`，即 mihomo 的
   `PUT /proxies/PROXY {"name":"优选03"}`
3. 顺手 `DELETE /connections` 把已有连接断掉，避免旧路由被长连接吊着
4. 当前选择写进 `data/state.json`

**全程没有进程重启，没有配置文件写入，窗口不会闪。** mihomo 的代理组选择是运行时状态。

只有这些情况才写配置文件并让内核热重载（`PUT /configs`，仍然是原地重载不是重启）：

- 优选产生了新的节点列表
- 订阅更新
- 改了分流规则 / 端口 / 国内直连开关

## 优选是怎么做的

问题背景：走 Cloudflare 的节点，域名解析出来的是 CF 的 Anycast 地址。同一个 IP
在不同时段可能被调度到不同机房，实测过同一个域名三小时内分别落到法兰克福、
阿姆斯特丹、伦敦，延迟从 0.8 秒飘到 3.9 秒。

做法（`optimizer.go`）：

1. 从订阅节点里挑一个 `type=vmess && network=ws` 的作为模板，取它的
   `servername`（SNI）、`ws-opts.path`、`ws-opts.headers.Host`
2. 读 `data/candidates.txt` 里的候选 IP 池（首次运行写入约 256 个内置地址）
3. 对每个 IP 发**真实的 WebSocket 升级请求**：TLS 连到该 IP 但 SNI 用模板的域名，
   发 `Upgrade: websocket`，**只有返回 101 才算可用**。这一步是关键：能建 TLS
   不代表能转发节点流量，很多边缘地址 TLS 通但 WS 被拒
4. 每个 IP 测 N 轮（默认 3），取中位数，失败的轮次按 0.4 秒加罚分
5. 按分数排序，取前 K 个（默认 16）重写成节点，名字形如
   `优选01 · 104.27.30.1 · 224ms`
6. 实测可用的 IP 追加回 `candidates.txt`，所以池子越用越准
7. 给内核热重载

模板节点的 SNI / path / Host **保持不变**——Cloudflare 就是靠这三个路由的，
换的只是边缘地址。

## 系统代理的四道护栏

代理客户端最容易造成的伤害就是"把用户搞断网"。`sysproxy.go` 里做了四件事：

**1. 别人在用就不抢**
启动时枚举进程名（`flclash.exe` / `clash-verge.exe` / `sing-box.exe` …），只要检测到
别的代理客户端在跑，就**只在自己端口上待着，绝不改注册表**。判定用精确进程名而不是
子串，因为 Zenith 自己的内核就叫 `mihomo.exe`，早期版本用子串匹配时把自己当成了外人。

**2. 先快照再动手**
写注册表之前把 `ProxyEnable` / `ProxyServer` / `ProxyOverride` / `AutoConfigURL`
存进 `data/proxy-snapshot.json`。

**3. 退出归还原主，原主没了就关掉**
还原时检查快照里那个端口现在有没有人监听。如果原来的客户端已经退出了，
把代理指回去等于让用户断网，所以这种情况直接关闭代理。

**4. 死端口兜底**
后台每 10 秒检查一次：如果系统代理指向的端口没人监听，立刻还原或关闭。

**顺序很重要**：退出时必须**先停内核再还代理**。反过来做的话，"那个端口还有人监听吗"
的检查会被自己的内核回答"有"，然后把代理留在一个马上就会失效的端口上。

## 订阅解析

`subscription.go` 能处理两种形态：

- clash / mihomo 的 YAML 配置（`proxies:` 段）
- 分享链接列表：`vmess://` `vless://` `trojan://` `ss://` `hysteria2://`
- 以及被 base64 包了一层的上述内容

抓取时**强制不走系统代理**（`Transport.Proxy = nil`）。原因很实际：Zenith 自己
可能就是系统代理，如果启动阶段通过自己去抓订阅，而内核还没起来，就会死锁。

## 为什么不用现成的 YAML 库

需要解析的结构非常有限（就是 `proxies:` 段），而真实机场的输出有一个恶心的形状：

```yaml
proxies:
- alpn:            # 列表项在列 0
  - h2             # 元素也在列 0
  - http/1.1
  name: N1         # 同级键在列 2
  ws-opts:
    headers:
      Host: x
```

`proxies:` 的列表项和它的键根本不在同一层缩进上。一个按缩进判断的通用解析器要花不少
力气才能吃下它，而这点需求不值得引入依赖。手写的解析器只有 200 行，逻辑是：
**以 `- ` 开头的是序列项，否则是映射键**，容器用栈按缩进关闭。

## 踩过的坑

按发现顺序记录，都是实测才暴露的：

| 问题 | 现象 | 原因 |
|---|---|---|
| 订阅返回 404 | 抓取失败 | Go 里把 `Path` 和 `RawPath` 同时设成转义形式，中文路径被编码两次 |
| 解析出 0 个节点 | 订阅有效但没节点 | 解析器要求子块缩进必须更深，而这个机场的列表项与键同缩进 |
| 所有边缘都不可用 | 优选 0 结果 | `Sec-WebSocket-Key` 用零填充的时间戳生成，base64 解出来是 16 个 0 字节，Cloudflare 直接 400 |
| 内核拒绝配置 | `did not find expected '-' indicator` | 列表项的第一个键被放到了下一行 |
| 内核拒绝配置 | `did not find expected key` | 缩进多加/少加了 2 格，嵌套的 `ws-opts.headers` 被拉平 |
| 内核拒绝节点 | `has unset fields: alterId` | vmess 的 `alterId` 即使是 0 也必须显式写出 |
| 窗口关掉后程序还在 | 只能手动杀进程 | `watchWindow` 提前返回后主协程就结束了，后来改成兜底循环 |
| 日志每 10 秒重复一次 | 刷屏 | `Enable()` 在"代理已经是我的"时提前返回 nil，调用方无法区分"已持有"和"刚拿到"，改成返回 `took bool` |

## 安全边界

- 系统代理只绑定回环，没有 `allow-lan`
- 内核控制端口用随机 secret（每次启动生成）
- 订阅抓取关闭了证书校验。这是一个有意的取舍：部分机场的证书链不完整，
  严格校验会导致订阅完全拉不动。**抓取的内容只用于生成配置，不做任何执行**
- 自定义规则经 `ValidateRule` 校验类型白名单，防止一条写错的规则让整个配置无法加载
